## Cambios y decisiones

- Alta de reciclaje por cámara QR y confirmación de solo lectura. Material,
  cantidad, fecha/hora UTC y coordenadas llegan en JSON v1 del tacho.
- Política única calcula EcoPuntos; nunca se acepta el saldo indicado por QR.
  Perfil/saldo siguen locales y simulados, con persistencia y actualización
  reactiva del dashboard. No existe acreditación en una cuenta remota.
- Migración SQLite v1 → v2 aditiva; recibo único y registro en una transacción.
  Reescaneo no duplica, conflicto de payload se rechaza y recibo se conserva
  después de borrar. Trigger impide alterar datos del tacho; editar la nota
  local conserva CRUD sin cambiar puntos. CRUD/borradores de
  registros manuales antiguos siguen funcionando y no se borra su información.
- Mapa geográfico con FlutterMap/OpenStreetMap opcional; catálogo importable
  en SQLite y ubicación GPS puntual para Haversine. Datos desconocidos/demos
  quedan fuera de proximidad real. No se guarda ubicación del teléfono.
- Eliminados botones Sugerencias de Inicio y Perfil, conservando datos/ruta
  históricos para no borrar información ajena.
- Monitor de internet con estados desconocido/conectado/sin conexión; banner
  elimina “Sin conexión” al recuperar internet y mantiene aviso de simulación.
- Permisos Android de cámara/ubicación pedidos al usar esas funcionalidades;
  escáner libera cámara en background y al salir. ML Kit lector QR incluido.
- Versión 0.3.0+3. Contrato/catálogo y QR sintético documentados en
  [QR y ubicaciones](../QR_Y_UBICACIONES.md). Fuentes y README actualizados.

## Límites

No hay hardware emisor ni coordenadas reales suministradas. El ejemplo 0,0
es sintético; el equipo debe cargar el catálogo verificado. No se certifica
distancia real UNP ni lectura desde un tacho físico. El QR aún no está firmado
ni validado remotamente: deduplicación por instalación, no entre teléfonos.
El permiso GPS y lectura por lente física requieren comprobación en teléfono.
No hay backend, sincronización o cuenta remota. No se modificó la firma release.

### Compatibilidad de instalación

El APK 0.2.0 descargado de CI usa certificado debug SHA-256
`528d815740ab478b2f0a27eb7bea231b555d88a14d7789d9159dd6b6e33fbe33`.
El entorno debug local usa `93e98960b627c624457e3d33b866f48a1857a6c1f4e7025fbee611848249d485`.
Son firmas diferentes: Android no permite actualizar una sobre otra. No se
debe desinstalar la app del teléfono si se necesitan conservar sus datos.
Para actualizar esa instalación se necesita la clave original de firma o
respaldar/restaurar sus datos debug mediante ADB antes de cambiar de firma.
La migración SQLite preserva datos al actualizar con una firma compatible;
no elude las restricciones de instalación de Android. Usar dispositivo/emulador
de prueba para el nuevo APK; nunca borrar datos para demostrar persistencia.
