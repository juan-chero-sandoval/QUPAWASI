# C04 · Compatibilidad con Supabase

El adaptador de lectura se incorpora a la composición Flutter. Al compilar
sin configuración de Supabase se abre la app local de Unidad II. Con la
configuración disponible, **Perfil → Más → Probar conexión** consulta una fila
como máximo de `public.categories`. Una respuesta válida con cero filas también
confirma el acceso al endpoint. El catálogo y los movimientos mostrados en las
pantallas siguen usando SQLite.

## Compilar para una futura prueba de conexión

Desde `apps/mobile`, con el SDK de Flutter fijado en CI, usa la URL del proyecto
y su clave publicable `sb_publishable_…`. Los parámetros de compilación se
incluyen en el APK. La URL y la clave pública se obtienen en el diálogo
**Connect** del proyecto. [Claves de API de Supabase](https://supabase.com/docs/guides/getting-started/api-keys)

```sh
flutter pub get --enforce-lockfile
flutter build apk --debug \
  --dart-define=SUPABASE_URL=https://TU_PROYECTO.supabase.co \
  --dart-define=SUPABASE_PUBLISHABLE_KEY=sb_publishable_REEMPLAZAR
```

El APK se escribe en `build/app/outputs/flutter-apk/app-debug.apk`. Para la
variante exclusivamente local, omite ambos `--dart-define`.

## Contrato de lectura

| Área | Tablas y condiciones |
| --- | --- |
| Catálogo | `categories`, `rewards`, `recycle_points`, `materials` y `career_codes`. Los catálogos con `enabled` se filtran por `true`. Los tachos exponen información y coordenadas de catálogo. |
| Cuenta | `profiles` por el UUID del usuario. `activity`, `redemptions`, `suggestions` y `notifications` se filtran por `user_id`. |
| Respuestas y configuración | `suggestion_replies` se filtra por `suggestion_id`. `app_settings` requiere sesión. El servidor define las filas visibles. |
| Operaciones del servidor | El alta de capturas, secretos de dispositivo, acceso a `device_url`, suscripciones web, acreditación de puntos y canjes remotos quedan para una integración posterior. |

Las consultas autenticadas reciben el UUID y el token de acceso de una sesión
Supabase Auth desde la futura integración de inicio de sesión. En Supabase,
habilita Data API y configura permisos `SELECT` y seguridad por filas (RLS).
La comprobación manual requiere que `anon` pueda consultar `categories`.
Para datos de cuenta, restringe las filas al dueño mediante `auth.uid()` y
comprueba la propiedad de la sugerencia al permitir leer sus respuestas.
Limita la configuración a valores destinados al cliente móvil. Los filtros de
la app sirven para consultar. La autorización se aplica en el servidor.
[Data API](https://supabase.com/docs/guides/api)
[Seguridad por filas](https://supabase.com/docs/guides/database/postgres/row-level-security)

Las filas conservan la estructura JSON de la API, incluidos los valores nulos,
JSONB y los nombres de los enums de `activity`. La definición compartida es la
referencia de columnas. Esta entrega no ejecuta DDL ni introduce migraciones.
